## Техническое задание на разработку веб-платформы бизнес-инкубатора 

1. **Описание и цели проекта**  
    <u>Цель проекта:</u> Создать веб-платформу для студенческого бизнес-инкубатора, которая позволит привлекать реальные заказы на разработку IT-продуктов, демонстрировать навыки студентов и управлять процессом выполнения заказов.  
    <u>Тип приложения:</u> Веб-приложение.

2. **Роли в системе и их права**  
    **В системе предусмотрено 4 уровня доступа:**
    1. <u>Гость _(Незарегистрированный пользователь)_</u>
        * Просмотр публичных страниц сайта _(такие как Главная, О нас, Команда)_.
        * Регистрация в качестве Заказчика.
    2. <u>Заказчик</u>
        * Авторизация в Личном кабинете _(ЛК)_.
        * Создание новой заявки на проект.
        * Просмотр списка своих заявок и их статусов.
        * Просмотр контактов Менеджера для связи по конкретному заказу.
    3. <u>Студент _(Исполнитель)_</u>
        * Определенную специализацию в профиле _(такие как Frontend, Backend, Аналитик, Тестировщик, Дизайнер и т. д.)_.
        * Видит проекты, на которые он назначен.
        * Видит состав команды, работающей с ним над проектом.
        * Может оставлять внутренние комментарии или ссылки на репозитории/макеты для преподавателя. _(ОПЦИОНАЛЬНО)_
    4. <u>Администратор _(Преподаватель/Менеджер)_</u>
        * Имеет полный доступ ко всем заказам в системе.
        * Может менять статусы заказов.
        * Назначает на заказ команду исполнителей 
        * Обсуждает бюджет с заказчиком _(вне сайта, в Telegram)_ и при необходимости фиксирует его в карточке заказа для внутреннего учета.

3. **Жизненный цикл заказа _(Бизнес-логика)_**  
    **Заказ в системе проходит через следующие статусы:**
    1. <u>Создан</u> — Заказчик заполнил форму в ЛК. Заявка появилась у Админа.
    2. <u>Взят в работу</u> — Админ связался с заказчиком в Telegram, обсудил детали и бюджет. Админ назначил на проект команду студентов и перевел заказ в этот статус.
    3. <u>Тестируется</u> — Студенты закончили разработку. Внутренняя проверка проекта тестировщиком или преподавателем.
    4. <u>Готов</u> — Преподаватель/Менеджер успешно принял работу у студентов, передал готовый продукт заказчику _(через Telegram)_ и закрыл заказ на сайте.
    5. <u>Отменен</u> — Заказ неактуален, не сошлись по бюджету или заказчик передумал.

4. **Структура веб-приложения**
    1. **Публичная часть _(Сайт-визитка)_**  
        Состоит из нескольких вкладок/страниц:
        * <u>Главная:</u> Описание инкубатора, какие задачи вы решаете, преимущества работы с вами.
        * <u>Услуги:</u> Что конкретно вы делаете _(веб-сайты, мобильные приложения, боты, дизайн)_.
        * <u>Команда:</u> Карточки студентов _(Фото, Имя, Роль — Backend, Frontend, QA и т. д., можно добавить стек технологий каждого)_.
        * <u>Контакты:</u> Общая информация.
        * <u>Кнопка «Оставить заказ»:</u> Ведет на страницу регистрации/авторизации для Заказчика.
    2. **Личный кабинет Заказчика**
        * <u>Дашборд:</u> Список всех заказов заказчика в виде карточек или таблицы.
        * <u>Создание заказа:</u> Форма _(Название проекта, Описание задачи, Ссылки на примеры/ТЗ, Желаемые сроки)_.
        * <u>Страница заказа:</u> Отображает текущий статус _(например, "Тестируется")_, и кнопку/ссылку «Связаться с менеджером в Telegram». Обсуждение бюджета и деталей происходит именно там.
    3. **Личный кабинет Студента**
        * <u>Мои задачи:</u> Список проектов, куда студент добавлен как участник.
        * <u>Детали проекта:</u> Описание от заказчика, дедлайн, список коллег по команде _(кто фронт, кто бэк и т. д.)_.
    4. **Панель Администратора _(Преподавателя)_**
        * <u>Управление заявками:</u> Таблица всех заявок в системе.
        * <u>Карточка заявки:</u> Возможность редактировать заявку, менять статус.
        * <u>Формирование команды:</u> Выпадающий список всех студентов с возможностью множественного выбора _(мультиселект)_ для прикрепления к заказу.
        * <u>Управление пользователями:</u> Добавление/удаление профилей студентов, назначение им ролей _(Специализаций)_.
    5. **Требования к коммуникации и сдаче работ**
        1. <u>Общение с заказчиком:</u> Платформа не имеет встроенного чата. Вся коммуникация выведена в Telegram. На сайте в карточке заказа закрепляется ссылка на Telegram-аккаунт Менеджера _(Преподавателя)_.
        2. <u>Сдача проекта:</u> Студенты сдают работу _(ссылки на код/архивы)_ преподавателю напрямую или через внутренние заметки к заказу. Преподаватель сам передает финальный результат Заказчику.
    6. **Рекомендации по технологиям _(Стек)_**
        1. <u>Frontend _(Клиентская часть)_:</u> Next.js.
        2. <u>Backend _(Серверная часть)_:</u> Python, Go.
        3. <u>База данных:</u> PostgreSQL.
